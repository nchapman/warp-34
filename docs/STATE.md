## AVX2 CPU MoE Evaluator Optimization (`moe_cpu_bridge::eval`, completed & verified)

- **Scope:** Audited and optimized the AVX2 + FMA + F16C path in `crates/w34-host/src/moe_cpu_bridge/eval.rs` on AMD EPYC 7R13 (`Zen 3`, `avx2,fma,f16c`, no AVX-512) while preserving 0-ULP bit-for-bit parity (`to_bits()`) against `expert_portable` and `expert_avx512`.
- **Key Optimizations:**
  - **0-ULP AVX2 in-register `H_64` block-Hadamard (`hadamard64_f32_avx2`):** Replaced scalar `hadamard64_f32_inplace` on `x86_64` (`supported()`) with an 8-register `__m256` butterfly using `_mm256_permute_ps` + `_mm256_fmadd_ps` (`h = 1, 2`), `_mm256_permute2f128_ps` + `_mm256_fmadd_ps` (`h = 4`), and vertical `__m256` add/sub stages (`h = 8, 16, 32`), cutting 96×1024 `H_64` time on Zen 3 from `90.0 µs` to **`18.8 µs`** (`4.8×` faster) with 0-ULP parity.
  - **AVX2 8×8 matrix transpose in `prepare_x_perm*` (`transpose_8x8_avx2`):** Replaced scalar 16×8 scatter stores in `prepare_x_perm`, `prepare_x_perm_grouped`, `prepare_x_perm_f16c`, and `prepare_x_perm_f16c_g64` with contiguous 256-bit loads/stores via `_mm256_unpacklo/hi_ps`, `_mm256_shuffle_ps`, and `_mm256_permute2f128_ps` while keeping sequential group-sum accumulation in original input order (`56.0 µs -> 33.9 µs` at `g=64`, `53.2 µs -> 31.4 µs` at `g=128`).
  - **Register-pressure-aware `row_tile_avx2` & `T=4` prefill tiling (`rows_avx2`):** Kept interleaved `(lo, hi)` nibble accumulation for `R * T <= 2` (`nt = 1` decode) and split `acc_lo` / `acc_hi` accumulation within each `g` iteration for `R * T > 2` (`T in {2, 4}` with `R = 2`) so `R = 2, T = 2` fits inside the 16 architectural `ymm` registers without inner-loop stack spills, and enabled `T = 4` token tiling in `rows_avx2`.

## Pipeline Hand-Off Optimization Across Speculative Decoding, Collectives, PLE, Vision, MoE Offload, and Scheduling (`feat/pipeline-handoffs`, completed & verified)

- **Scope:** End-to-end elimination of host-device synchronization stalls, redundant PCIe copies, per-chunk/per-step intermediate kernel launches, and host heap churn across all 9 audited pipeline hand-off points (`§1.1–§1.5`, `§2.1–§2.4`).
- **Key Optimizations:**
  - **Pipelined `MTP` `ingest_and_propose` & On-Device Eager Multi-Step Chaining (`proposer.rs`, `mtp/propose.rs`):** Removed the `self.current.is_none()` gate in `SpeculativeProposer::ingest_and_propose` so `MTP` runs the fused prefill/verify ingest + step-0 draft inside `forward_selected_rows_with_tap_hook` instead of paying a duplicate `k`-step launch inside `propose_for_request`. Added `forward_inner_with_device_step` so eager `k > 1` `MTP` chains steps `1..k` directly from `draft_ids_out_device[step - 1]` and performs a single D2H copy + stream synchronize for all `k` draft tokens at the end of step `k - 1`.
  - **Device-Resident `TP > 1` `DFlash2` Top-`k` Gather, On-Device Greedy Selection & Disjoint Double-Buffered Collectives (`op_collectives.cu`, `collectives.rs`, `dflash.rs`, `proposer.rs`, `build.rs`):** Added `w34_tp2_all_gather_topk_f32_i32` and `w34_tp4_all_gather_topk_f32_i32` and wired `DFlash2Rank::ensure_select_greedy_graph` and `forward_select_greedy_tp` to merge per-rank top-`k` candidates and run `w34_dflash_select_greedy_i32` on-device across `TP=2`/`TP=4` (including inside a single captured CUDA Graph per rank), cutting `TP > 1` `DFlash2` D2H traffic from `15 × 16 × 8 B = 1,920 B/rank` to `15 × 4 B = 60 B`. Isolated all small single-CTA collectives (`broadcast_i32`, `all_gather_top1_f32_i32`, `all_gather_topk_f32_i32` `<= 4,096 B`) into fixed `4,096 B` halves of `Signal::end[0..128]` (`small_epoch_ptr`) and anchored `stage0..stage3` `odd` epoch offsets to `max_stage_bytes_per_epoch` via `Signal::end[128][0]` (`stage_epoch_ptr`) so back-to-back variable-size collectives never overlap across epochs. Updated `crates/w34-kernels/build.rs` (`per_source_header_digest`) to compute per-`.cu` transitive `#include` and symbol-filtered `w34_cuda.h` digests.
  - **Target `skip_host_greedy` Fast Path (`model/forward.rs`, `model/batch.rs`, `model/generation.rs`):** Added `forward_selected_rows_maybe_skip_greedy` so `forward_selected_rows_into_with_tap_hook` skips the redundant greedy argmax (`all_gather_top1_f32_i32`), D2H copy, and `stream.synchronize()` whenever `skip_host_greedy` is set (every GPU-sampled decode step and speculative verify round).

## Rust CPU MoE Bridge Migration & Performance (completed & verified)

- **Architecture:** Host SIMD `u4b8` evaluation, dynamic physical-core worker pool, responder, and mapped mailbox ownership live in `crates/w34-host/src/moe_cpu_bridge.rs` and `crates/w34-host/src/moe_cpu_bridge/eval.rs`. `crates/w34-kernels/csrc/ops/op_moe_cpu_bridge.cu` contains only stateless GPU mailbox kernels and explicit-pointer launch wrappers (`w34_moe_hybrid_submit_and_pull`, `w34_moe_hybrid_wait_and_add`).
- **Dynamic core topology & lock-free dispatch:** `detect_worker_cpus()` queries `sched_getaffinity` and deduplicates SMT siblings via `/sys/devices/system/cpu/cpu*/topology/{thread_siblings_list,physical_package_id,die_id,core_id}` (capped at `32` workers, with `available_parallelism` fallback), pinning the responder as worker `0` on `cpus[0]` and spawning `cpus.len() - 1` background workers on `cpus[1..]`. `Wake` tracks `sleeping` workers with `SeqCst` ordering so `FUTEX_WAKE` syscalls are skipped while workers are in their user-space spin window.
- **Active-token compaction & register-resident L1 weight tiling:** `evaluate_into` compacts sparse prefill routing into `RoutingScratch` (`active_toks` + `tok_to_compact`), preparing only tokens routed to at least one CPU cold expert, reducing expert outputs with AVX2/F16C (or portable fallback), and parking `moe-responder` via `PrefillGuard` so all physical cores execute prefill jobs 1-to-1.

- **Safe failure propagation:** Decode evaluation errors acknowledge the mailbox with `status = 1` (skipping stale output addition on the GPU) and latch a sticky host failure on the owning `CudaStream`. At serving tick boundaries (`engine_worker.rs`), `require_healthy_host_compute` escalates to the supervised worker boundary, closing ingress and notifying active and queued requests rather than continuing to serve from corrupted KV/recurrent state.
