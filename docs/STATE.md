- Profiled and eliminated six multi-client long-trajectory bottlenecks across both `MTP` and `DFlash2`:
  - **Prompt-frontier preservation in `MambaRadixCache` (`radix.rs`, `model/batch.rs`, `engine_worker/decode.rs`):** Tagged unverified decode-tail donations with `is_decode_tail: true` and tightened `evict_mamba` / `evict_full_pages` / `alloc_state_slot_preserving_leaves` so Priority 1 tombstones only single-child internal nodes that have a non-decode-tail Mamba descendant (`has_non_decode_mamba_descendant`), Priority 2 reclaims unverified decode-tail leaves whose parent prompt frontier still holds a live Mamba snapshot (`is_reclaimable_decode_tail_leaf`), and Priority 3 falls back to standard LRU—stopping `12k`-token multi-turn trajectories from tombstoning active prompt frontiers (`hit_ratio`: `13.5% → 88.5%` on `TP=1 swe-c8-burst`).
  - **Multi-slot `DFlash2` KV cache & GPU D2D cross-slot KV copy (`dflash.rs`, `mtp.rs`, `proposer.rs`, `proposer/scheduled.rs`):** Partitioned `DFlash2` KV pool into `max_num_seqs.clamp(2, 8)` independent batch slots (`256` physical pages = `4,096` ring tokens per slot, `2,048` pages total) with ring-buffer window validity checking (`dflash_slot_has_prefix`) and GPU D2D `copy_kv_from_slot` for both `MTP` and `DFlash2` when a session resumes in or shares a prefix with another slot.
  - **3-Tier LRU-aware slot affinity (`proposer/scheduled.rs`, `proposer.rs`):** Ranked batch slot candidates as Tier 2 (exact session continuation, `prefix_len >= tokens.len() / 2`), Tier 1 (empty slot), and Tier 0 (diverged slot ordered by oldest `last_used_tick` LRU), preventing stale long sessions from pinning slots across workload phases (`TP=1 DFlash2 swe-c8-burst`: `23.63 → 83.04 tok/s`).
  - **Serialized prefill admission & multi-client `TP=2` GDN state pools (`engine_worker/runner.rs`, `dflash.rs`, `mtp.rs`, `model/engine.rs`):** Required `sched.active.iter().all(|s| s.is_prefill_complete())` before admitting a second long prefill so concurrent `12k`-token admissions pipeline cleanly with `MambaRadixCache` prefix reuse instead of interleave-thrashing `2048`-token chunks; scaled `TP=2` serving state pools to `64` (`MTP`) and `80` (`DFlash2`) GDN slots.
  - **Bounded `PrefixMemo` growth (`proposer.rs`):** Replaced `shrink_to_fit()` + doubling `resize()` on `100+ MiB` `PrefixMemo.features` buffers with `512`-row (`~5 MiB`) chunked `reserve_exact` (`grow_memo_features`), cutting 10-minute 27B soak host RSS growth from `3,168 MiB` to `1,774 MiB`.

## Concurrent 27B MTP serving fixes & 4-sustained / 8-burst soak verification

- Resolved the three concurrent serving bottlenecks exposed by the `0105610` 27B `4` sustained / `8` burst soak (`--kv-pages 4096 --max-num-seqs 4 --max-model-len 16384`, TQ4, MTP-3 on one RTX 3090 Ti), with regression-first tests (`concurrent_27b_mtp_serving_allocates_verify_and_burst_state_slots` in `tests/worker_capacity.rs`, `batched_mtp_max4_handles_8_burst_and_reuses_warm_prefixes` in `tests/speculative_handoff.rs`, and `serving_budget_offloads_embed_when_concurrent_mtp_state_slots_exceed_gpu_embed_slack` in `src/model/tests.rs`):
  - **24-slot GDN pool via serving-state-aware embedding placement (`mtp.rs`, `model/engine.rs`, `model/rank.rs`):** `mtp::serving_state_slots(4, 3)` requests `24` GDN slots (`12` active private + `4` locked radix checkpoints + `4` batched verify extras + `4` cached burst checkpoints), and `plan_host_embed_with_serving_budget` offloads `2.37 GiB` `embed_tokens` to `MappedHostBuffer` when GPU-resident embeddings would squeeze desired serving state/vision reserves below target (lifting the live 27B pool from **12 → 24 GDN slots** while lowering steady VRAM from `23,113` to `22,447 MiB`).

## 1–2× RTX 3060 Ti (8 GB, `sm_86`) & 1–2× RTX 4060 Ti (16 GB, `sm_89`) Qualification & Fixes (`3060-4060`, verified)

- **Scope:** Provisioned and qualified `warp-34` across **1–2× RTX 3060 Ti (`8,192 MiB`, `sm_86`, 38 SMs, 3 MiB L2, CUDA 13.2)** and **1–2× RTX 4060 Ti (`16,380 MiB`, `sm_89`, 34 SMs, 32 MiB L2, CUDA 13.0 / `ptxas V13.0.88`)** in parallel across `TP=1` and `TP=2`, while verifying zero regressions on **1–2× RTX 4090 (`24,564 MiB`, `sm_89`, 128 SMs, 72 MiB L2, CUDA 13.2)**.
- **Root Causes & Fixes:**
  - **CUDA 13.0 `ptxas` 1-Byte Packed `__half` Miscompile on `TQ4` Scales (`tq4_kv_common.cuh`, `op_qsa.cu`):**
    - On CUDA 13.0 (`ptxas V13.0.88` on `sm_89`), wrapping `block_tq4_0` (`__half d; uint8_t qs[64];`) and `qsa_block_tq4_0` in `#pragma pack(push, 1)` (`alignof == 1`) forced `ptxas` to split 16-bit `__half` scale stores into two `STG.E.U8` byte stores and triggered a peephole bug that compiled the low byte of `__half d` as `F2I.U8.F16.TRUNC.NTZ` (float-to-uint8 value conversion instead of bit extraction), corrupting the mantissa of every `TQ4` scale `d` under CUDA 13.0.
    - Removing `#pragma pack(push, 1)` (while enforcing `static_assert(sizeof == 66 && alignof == 2)` for `block_tq4_0` and `sizeof == 68 && alignof == 4` for `block_q8_0_64`) emits single aligned `STG.E.U16` / `LDG.E.U16` instructions, fixing `w34 dump-diff --kv-format tq4 --compare-tp2` (`target_max_rel_l2 = 0.045879`, `match = true`), `test_gpu_hc_ple_qsa_kernels_parity` (at original `2.6e-2` tolerance), and doubling `27B TP=2 DFlash2` throughput on 4060 Ti from `56.2 tok/s` (`0.97` accepted drafts) to **`111.91 tok/s` (`4.25` accepted drafts, `3.59×`)**.

## Rust CPU MoE Bridge Migration & Performance (completed & verified)

- **Architecture:** Host SIMD `u4b8` evaluation, dynamic physical-core worker pool, responder, and mapped mailbox ownership live in `crates/w34-host/src/moe_cpu_bridge.rs` and `crates/w34-host/src/moe_cpu_bridge/eval.rs`. `crates/w34-kernels/csrc/ops/op_moe_cpu_bridge.cu` contains only stateless GPU mailbox kernels and explicit-pointer launch wrappers (`w34_moe_hybrid_submit_and_pull`, `w34_moe_hybrid_wait_and_add`).
- **Dynamic core topology & lock-free dispatch:** `detect_worker_cpus()` queries `sched_getaffinity` and deduplicates SMT siblings via `/sys/devices/system/cpu/cpu*/topology/{thread_siblings_list,physical_package_id,die_id,core_id}` (capped at `32` workers, with `available_parallelism` fallback), pinning the responder as worker `0` on `cpus[0]` and spawning `cpus.len() - 1` background workers on `cpus[1..]`. `Wake` tracks `sleeping` workers with `SeqCst` ordering so `FUTEX_WAKE` syscalls are skipped while workers are in their user-space spin window.
- **Active-token compaction & register-resident L1 weight tiling:** `evaluate_into` compacts sparse prefill routing into `RoutingScratch` (`active_toks` + `tok_to_compact`), preparing only tokens routed to at least one CPU cold expert, reducing expert outputs with AVX2/F16C (or portable fallback), and parking `moe-responder` via `PrefillGuard` so all physical cores execute prefill jobs 1-to-1.
- **Pool microbenchmark (`benchmark_flash_next_pool` on Ryzen 9 7950X3D):** `tokens=1` median **152.4 µs** (`p90 165.7 µs`), `tokens=4` median **427.6 µs** (`p90 451.9 µs`), `tokens=16` median **1,215.1 µs** (`p90 1,233.5 µs`), `prefill tokens=6144 (16x12 active)` median **2,097.2 µs** (`45×` faster than the `94,709.7 µs` uncompacted baseline).
- **Safe failure propagation:** Decode evaluation errors acknowledge the mailbox with `status = 1` (skipping stale output addition on the GPU) and latch a sticky host failure on the owning `CudaStream`. At serving tick boundaries (`engine_worker.rs`), `require_healthy_host_compute` escalates to the supervised worker boundary, closing ingress and notifying active and queued requests rather than continuing to serve from corrupted KV/recurrent state.
